# Version v0.5 Implementation Instructions & Agent Task Prompt

## Overview & Goal
This document provides step-by-step implementation instructions and a machine-readable task specification for **Version v0.5: Property Manager Review Workflow, Audit History & Automated 12-Month Lease Issuance** of the RentalPropertyManager web application (.NET 10 ASP.NET Core MVC & EF Core).

In v0.5, Property Managers gain the ability to review submitted applications via AJAX modals (`Approve`, `Return`, `Deny`), record required review comments, automatically generate a 12-month `Lease` record locking in `MonthlyRent` upon approval, enforce double-lease collision checks, and track all application status transitions and system actions via an audit history timeline view component (`ActionHistory` & `Review`).

---

## 1. Technical Stack & Prerequisites
- **Target Framework**: .NET 10 ASP.NET Core MVC
- **Database & ORM**: SQL Server / Entity Framework Core 10 (Code-First Migrations)
- **Security & Authorization**: ASP.NET Core Identity Roles (`[Authorize(Roles = "PropertyManager")]`)
- **Data Seeding Strategy**: Idempotent seeding using `Bogus` for .NET (`Data/DbInitializer.cs`)
- **UI Architecture**: Bootstrap 5, Razor Partial Modals (`_ReviewModal.cshtml`), Razor View Component (`StatusHistoryTimelineViewComponent`), Standalone JS (`wwwroot/js/review-workflow.js`)
- **Prerequisite Versions**: v0.1 (Identity & DB Context), v0.2 (Properties & Units CRUD), v0.3 (Wizard & Residence History), v0.4 (Application Submission & DB Filtered List)
- **Reference Documents**: `PROJECT_PLAN.md`, `meta-instructions.md`

### A. Data Models & Database Context
Create or update the following EF Core entities and add them to `ApplicationDbContext.cs`:

#### 1. `Review` Entity
* **Purpose**: Records individual formal review decisions submitted by Property Managers.
* **Properties**:
  * `Id` (int, Primary Key, Identity)
  * `ApplicationID` (int, Foreign Key to `Applications`, Required)
  * `UserID` (string, Foreign Key to `AspNetUsers`, Required)
  * `ReviewDate` (DateTime, Required, default `DateTime.UtcNow`)
  * `OutcomeApplicationStatusID` (int, Foreign Key to `ApplicationStatuses`, Required)
  * `Comment` (string, nullable for Approve, **Required** for Return and Deny, max 1000 characters)
* **Navigation Properties**: `Application Application`, `ApplicationUser User`, `ApplicationStatus OutcomeStatus`

#### 2. `Lease` Entity
* **Purpose**: Represents an active or historical lease agreement generated upon application approval.
* **Properties**:
  * `Id` (int, Primary Key, Identity)
  * `UnitID` (int, Foreign Key to `Units`, Required)
  * `ApplicationID` (int, Foreign Key to `Applications`, Required)
  * `StartDate` (DateTime, Required)
  * `EndDate` (DateTime, Required — calculated as `StartDate.AddMonths(12)`)
  * `MonthlyRent` (decimal, Required, precision `18,2` — **copied directly from `Unit.MonthlyRent` at lease signing**)
  * `CreatedAt` (DateTime, Required, default `DateTime.UtcNow`)
  * `ManagerNotes` (string, nullable, max 2000 characters)
* **Navigation Properties**: `Unit Unit`, `Application Application`

#### 3. `ActionType` Lookup Entity
* **Purpose**: Categorizes system audit log events.
* **Properties**:
  * `Id` (int, Primary Key, Identity)
  * `Name` (string, Required, max 100 characters, Unique)
* **Seed Values**: `Submission`, `StartReview`, `CompleteReview`, `Approve`, `Return`, `Deny`, `Withdraw`, `AddProperty`, `EditProperty`, `RemoveProperty`, `AddUnit`, `EditUnit`, `RemoveUnit`

#### 4. `ActionHistory` Audit Entity
* **Purpose**: Immutable audit log of status changes and administrative actions across the application lifecycle.
* **Properties**:
  * `Id` (int, Primary Key, Identity)
  * `ActionTypeID` (int, Foreign Key to `ActionTypes`, Required)
  * `UserID` (string, Foreign Key to `AspNetUsers`, Required)
  * `Date` (DateTime, Required, default `DateTime.UtcNow`)
  * `ApplicationID` (int, nullable, Foreign Key to `Applications`)
  * `UnitID` (int, nullable, Foreign Key to `Units`)
  * `PropertyID` (int, nullable, Foreign Key to `Properties`)
  * `FromStatus` (string, nullable, max 50)
  * `ToStatus` (string, nullable, max 50)
  * `FromObject` (string, nullable, JSON payload snapshot before action)
  * `ToObject` (string, nullable, JSON payload snapshot after action)
* **Navigation Properties**: `ActionType ActionType`, `ApplicationUser User`, `Application Application`, `Unit Unit`, `Property Property`

### B. Business Logic & Validation Rules

#### 1. Property Manager Application Review Rules
* **Role Gate**: Only users in the `PropertyManager` Identity role can access review endpoints or submit review decisions (`[Authorize(Roles = "PropertyManager")]`).
* **Eligible Statuses**: Only applications in `Submitted` (or `Under Review`) status can be reviewed.
* **Review Outcomes**:
  * **`Approve`**:
    * Performs double-lease collision check on the target unit.
    * Updates `ApplicationStatus` to `Approved` (terminal status).
    * Automatically generates a `Lease` record: `StartDate = Today`, `EndDate = Today.AddMonths(12)`, `MonthlyRent = Unit.MonthlyRent`.
    * Comment is optional.
  * **`Return`**:
    * Updates `ApplicationStatus` to `Returned` (allows applicant to correct and resubmit).
    * Comment is **MANDATORY** (explaining what needs correction).
  * **`Deny`**:
    * Updates `ApplicationStatus` to `Denied` (terminal status).
    * Comment is **MANDATORY** (explaining reason for denial).

#### 2. Double-Lease Prevention & Collision Check
* At the moment of `Approve`, the server queries `dbContext.Leases`:
  ```csharp
  bool hasActiveLease = await dbContext.Leases.AnyAsync(l => 
      l.UnitID == application.UnitID && 
      l.StartDate <= DateTime.UtcNow.Date && 
      l.EndDate >= DateTime.UtcNow.Date);
  ```
* If `hasActiveLease == true`, the approval action MUST be rejected with a user-friendly error message (`HTTP 400 Bad Request` or `ModelState.AddModelError`):
  > *"Cannot approve application: Unit {UnitNumber} currently has an active lease running until {EndDate:d}."*

#### 3. Audit History Logging (`ActionHistory`)
* Whenever an application status changes (`Submission`, `Approve`, `Return`, `Deny`, `Withdraw`), an `ActionHistory` record MUST be appended automatically:
  * `ActionTypeID`: ID matching the outcome action.
  * `UserID`: Current authenticated user ID.
  * `Date`: `DateTime.UtcNow`.
  * `ApplicationID`: Target application ID.
  * `FromStatus` & `ToStatus`: Status names before and after the transition.

### D. Controllers & Endpoints

#### `ReviewController` (`Controllers/ReviewController.cs`)
Annotate with `[Authorize(Roles = "PropertyManager")]`.

* **`GET /Review/ReviewModal/{applicationId}`**:
  * Loads application by `applicationId`. If not found or status is terminal (`Approved`, `Denied`, `Withdrawn`), returns `HTTP 404/400`.
  * Populates `AvailableOutcomes` SelectList with `Approved`, `Returned`, and `Denied` `ApplicationStatus` options.
  * Returns `PartialView("_ReviewModal", viewModel)`.

* **`POST /Review/CompleteReview`**:
  * Validates model state and required comment logic:
    * If `OutcomeStatus` is `Returned` or `Denied` and `string.IsNullOrWhiteSpace(model.Comment)`:
      ```csharp
      ModelState.AddModelError("Comment", "A comment is required when returning or denying an application.");
      ```
  * If outcome is `Approved`, performs active lease collision check on `UnitID`.
  * If validation fails: re-populates `AvailableOutcomes` and returns `PartialView("_ReviewModal", model)` with `HTTP 400 Bad Request`.
  * On success:
    * Updates `ApplicationStatusID`.
    * Creates `Review` record.
    * Creates `ActionHistory` record.
    * If `Approved`: creates `Lease` record (`StartDate = DateTime.UtcNow.Date`, `EndDate = DateTime.UtcNow.Date.AddMonths(12)`, `MonthlyRent = unit.MonthlyRent`).
    * Calls `await dbContext.SaveChangesAsync()`.
    * Returns `HTTP 200 OK` JSON `{ success = true, message = "Review completed successfully." }`.

#### 3. Standalone Client Script (`wwwroot/js/review-workflow.js`)
* Contained entirely in an external `.js` file loaded via `<script src="~/js/review-workflow.js"></script>` on the review page.
* **Modal Loader**: Intercepts review modal trigger button click, fetches `/Review/ReviewModal/${appId}`, injects HTML into `#reviewModalContainer`, shows Bootstrap modal, and invokes `wireUpReviewModal()`.
* **Post-Injection Wire-Up Helper**:
  ```javascript
  function wireUpReviewModal() {
      const form = document.querySelector('#reviewModal form');
      if (!form) return;

      form.addEventListener('submit', async function (e) {
          e.preventDefault();
          const formData = new FormData(form);

          try {
              const response = await fetch(form.action, {
                  method: 'POST',
                  body: formData,
                  headers: { 'X-Requested-With': 'XMLHttpRequest' }
              });

              if (response.ok) {
                  const result = await response.json();
                  if (result.success) {
                      const modalEl = document.getElementById('reviewModal');
                      const modal = bootstrap.Modal.getInstance(modalEl);
                      if (modal) modal.hide();
                      window.location.reload();
                  }
              } else {
                  const html = await response.text();
                  document.querySelector('#reviewModal .modal-content').innerHTML = html;
                  wireUpReviewModal(); // Re-bind after DOM replacement
              }
          } catch (err) {
              console.error('Error submitting review:', err);
          }
      });
  }
  ```

### F. Idempotent Data Seeding Updates (`Data/DbInitializer.cs`)

Ensure `DbInitializer.InitializeAsync()` handles v0.5 entities idempotently:

```csharp
// 1. ActionType Seed
if (!await dbContext.ActionTypes.AnyAsync())
{
    var actionTypes = new List<ActionType>
    {
        new() { Name = "Submission" },
        new() { Name = "StartReview" },
        new() { Name = "CompleteReview" },
        new() { Name = "Approve" },
        new() { Name = "Return" },
        new() { Name = "Deny" },
        new() { Name = "Withdraw" }
    };
    await dbContext.ActionTypes.AddRangeAsync(actionTypes);
    await dbContext.SaveChangesAsync();
}

// 2. Seeding Approved Applications & Active Leases via Bogus
if (!await dbContext.Leases.AnyAsync())
{
    var approvedStatus = await dbContext.ApplicationStatuses.FirstAsync(s => s.Name == "Approved");
    var submittedApps = await dbContext.Applications
        .Include(a => a.Unit)
        .Where(a => a.ApplicationStatusID == approvedStatus.Id)
        .ToListAsync();

    foreach (var app in submittedApps)
    {
        var lease = new Lease
        {
            UnitID = app.UnitID,
            ApplicationID = app.Id,
            StartDate = DateTime.UtcNow.Date.AddMonths(-2),
            EndDate = DateTime.UtcNow.Date.AddMonths(10),
            MonthlyRent = app.Unit.MonthlyRent,
            CreatedAt = DateTime.UtcNow.AddMonths(-2)
        };
        await dbContext.Leases.AddAsync(lease);
    }
    await dbContext.SaveChangesAsync();
}
```

## 6. Critical Red Flags & Pitfalls to Watch Out For

### 🚨 Red Flag 1: Embedded `<script>` Tags inside `_ReviewModal.cshtml`
* **The Problem**: Placing JavaScript directly inside partial view modals. When fetched dynamically via AJAX, inline scripts render as inline HTML blocks in DevTools rather than source files, preventing step-debugging and event listener binding.
* **The Solution**: Keep `_ReviewModal.cshtml` strictly HTML/CSS. Put all modal logic inside `wwwroot/js/review-workflow.js` and invoke `wireUpReviewModal()` immediately after injecting modal HTML into the DOM.

### 🚨 Red Flag 2: Hardcoding Lease Rent or End Date
* **The Problem**: Hardcoding rental amounts or using fixed 365-day additions (`Today.AddDays(365)`), which breaks on leap years or loses track of agreed rental rates if unit prices change later.
* **The Solution**: Always set `Lease.EndDate = StartDate.AddMonths(12)` and copy `Lease.MonthlyRent = Unit.MonthlyRent` directly at the moment of approval.

### 🚨 Red Flag 3: Missing Required Comment Validation on Return/Deny
* **The Problem**: Allowing Property Managers to return or deny applications without providing feedback comments to the applicant.
* **The Solution**: In `POST /Review/CompleteReview`, explicitly check `if (OutcomeStatus != Approved && string.IsNullOrWhiteSpace(model.Comment))` and add a `ModelState` error before processing.

### 🚨 Red Flag 4: Missing Dropdown Repopulation on Validation Error Path
* **The Problem**: Returning `PartialView("_ReviewModal", model)` on `ModelState` failure without re-populating `model.AvailableOutcomes`, causing `NullReferenceException` in Razor view select helpers.
* **The Solution**: Always call `PopulateOutcomes(model)` before returning `PartialView` on error paths.
