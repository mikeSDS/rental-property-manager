# Version v0.2 Implementation Instructions & Agent Task Prompt

## Overview & Goal
This document provides step-by-step implementation instructions, technical specifications, and a copy-paste agent prompt for **Version v0.2: Property & Unit Management (Modals, Active UnitType Server Rules, Applicant Unit Browsing & Bogus Seeding Setup)** of the `rental-property-manager` application.

This version builds directly on **Version v0.1**. Because v0.1 was implemented without Bogus, **Version v0.2 introduces the Bogus NuGet package setup** and configures `DbInitializer.cs` to generate realistic test data for Property Managers, Applicants, Properties, and Units upon application startup.

### D. `UnitType` Selection & Server-Side Validation Rules

1. **Active-Only Dropdown Filtering**:
   * Dropdowns for creating new units MUST display **active unit types only** (`ActiveBool == true`).
2. **Existing Inactive UnitType Exception**:
   * When editing an existing unit assigned to an inactive `UnitType`, that specific inactive `UnitType` **must** be appended to the dropdown list so it renders without error or data loss.
3. **Strict Server-Side Enforcement**:
   * On `POST` or `PUT` of a unit, the controller/PageModel MUST validate server-side that `UnitTypeID` corresponds to an active `UnitType` (or the unit's existing assigned inactive type).
   * If an invalid or inactive `UnitTypeID` is submitted for a new unit, the server MUST return an error: `"Selected unit type is inactive and cannot be assigned."`

### E. UI Shell, Partial Views & AJAX Modals

#### 1. Controllers / Pages
* **`PropertiesController`** (or `/Pages/Properties/`):
  * `Index` (GET): Accessible by `[Authorize(Roles = "PropertyManager")]`. Displays grid of properties.
  * `CreateModal` (GET partial / POST JSON): Renders `_PropertyModal.cshtml` partial inside a Bootstrap modal.
  * `EditModal` (GET partial / POST JSON): Renders edit modal.
  * `Delete` (POST): Removes or soft-deletes a property.
* **`UnitsController`** (or `/Pages/Units/`):
  * `CreateModal` (GET partial / POST JSON) & `EditModal`: Renders `_UnitModal.cshtml`.
  * `Browse` (GET): Accessible by **both Applicants and Property Managers**. Allows searching/filtering available units.

#### 2. Bootstrap Modal AJAX Interaction Pattern
* Form submission inside modals MUST be executed via JavaScript `fetch()` (AJAX).
* **Validation Failure (400 Bad Request)**: Server returns partial view HTML containing `text-danger` error spans. The JavaScript updates the modal body DOM without closing the modal.
* **Success (200 OK)**: Server returns `{ success: true }`. JavaScript hides the Bootstrap modal and reloads the grid table.

### F. Bogus Data Seeding Expansion (`DbInitializer.cs`)

Extend `Data/DbInitializer.cs` to seed realistic Properties and Units idempotently:

```csharp
// Seed Properties & Units using Bogus if Properties table is empty
if (!await dbContext.Properties.AnyAsync())
{
    var propertyFaker = new Faker<Property>()
        .RuleFor(p => p.Name, f => f.Company.CompanyName() + " Apartments")
        .RuleFor(p => p.StreetAddress, f => f.Address.StreetAddress())
        .RuleFor(p => p.City, f => f.Address.City())
        .RuleFor(p => p.State, f => f.Address.StateAbbr())
        .RuleFor(p => p.ZipCode, f => f.Address.ZipCode())
        .RuleFor(p => p.CreatedAt, f => DateTime.UtcNow.AddMonths(-f.Random.Number(1, 12)));

    var properties = propertyFaker.Generate(5);
    dbContext.Properties.AddRange(properties);
    await dbContext.SaveChangesAsync();

    var activeUnitTypes = await dbContext.UnitTypes.Where(ut => ut.ActiveBool).ToListAsync();
    if (!activeUnitTypes.Any())
    {
        throw new InvalidOperationException("No active UnitTypes found. Ensure UnitTypes are seeded before Properties.");
    }
    var activeUnitTypeId = activeUnitTypes.First().Id;

    var unitFaker = new Faker<Unit>()
        .RuleFor(u => u.UnitNumber, f => f.Address.BuildingNumber())
        .RuleFor(u => u.Bedrooms, f => f.Random.Number(1, 4))
        .RuleFor(u => u.MonthlyRent, f => f.Finance.Amount(900, 3200, 2))
        .RuleFor(u => u.UnitTypeID, activeUnitTypeId);

    var random = new Random();
    foreach (var property in properties)
    {
        var units = unitFaker.Generate(random.Next(3, 7)); // Generate 3-6 units per property
        foreach (var unit in units) { unit.PropertyID = property.Id; }
        dbContext.Units.AddRange(units);
    }
    await dbContext.SaveChangesAsync();
}
```

## 6. Critical Red Flags & Pitfalls to Watch Out For

1. 🚨 **Historical Migration Corruption (v0.1)**: Never edit `00000000000000_CreateIdentitySchema.cs`. Always generate incremental EF Core migrations (`dotnet ef migrations add ...`).
2. 🚨 **Account Lockout via Unconfirmed Email (v0.1)**: ASP.NET Core Identity defaults to `RequireConfirmedAccount = true`, causing silent login failures for new/seeded users. Disable this in `Program.cs` for local dev and set `EmailConfirmed = true` on all Bogus seeded users.
3. 🚨 **Non-Generic DbContext vs Custom User Fields (v0.1)**: Inheriting from non-generic `IdentityDbContext` ignores `UserType` and `CreatedAt`. `ApplicationDbContext` MUST inherit `IdentityDbContext<ApplicationUser>`.
4. 🚨 **Disappearing Inactive Unit Types During Edit (v0.2)**: Filtering dropdowns to active-only causes units assigned inactive types to clear or error on edit. Always append the unit's current `UnitType` to the SelectList if it is inactive.
5. 🚨 **Bypassing Server Validation via Client Controls (v0.2)**: Relying solely on client-side JS filtering allows POST requests to persist inactive unit types. Server-side validation in the controller is mandatory.
6. 🚨 **Bootstrap Modal Destruction on Validation Error (v0.2)**: Standard form POSTs trigger full page reloads, closing the modal and destroying error messages. Modal forms must POST via AJAX and swap partial HTML on error.
7. 🚨 **Authorization Leak on Modal Endpoints (v0.2)**: Protecting `Index` but forgetting `[Authorize(Roles = "PropertyManager")]` on modal partial endpoints (`/Units/CreateModal`) leaves endpoints exposed to direct HTTP requests.
8. 🚨 **Missing EF Core `.Include()` Navigation Calls (v0.2)**: Querying `Units` without `.Include(u => u.UnitType)` and `.Include(u => u.Property)` causes `NullReferenceException` during table rendering.
9. 🚨 **Missing Decimal Precision Configuration (v0.2)**: Omitting `.HasPrecision(18, 2)` on `MonthlyRent` causes EF Core migration warnings and SQL Server rounding errors.
10. 🚨 **Non-Idempotent Bogus Seeding (v0.1 & v0.2)**: Running Bogus generators without checking table state (`.Any()`) on every startup creates duplicate database records or throws primary key exceptions. Always wrap Bogus seed logic in `if (!await dbContext.TableName.AnyAsync())` checks.

## 5. Additional Clarifications & Implementation Notes

### A. AJAX Modal Response Specifications
* **Validation Failure Response** (HTTP 400):
  * Content-Type: \`text/html\`
  * Body: Partial view HTML containing the original form with validation error messages displayed in \`<span class="text-danger">\` elements.
  * Example: \`<span class="text-danger">The UnitNumber field is required.</span>\`
  * Modal remains open; user corrects and resubmits.

* **Success Response** (HTTP 200):
  * Content-Type: \`application/json\`
  * Body: \`{ "success": true }\`
  * Modal closes; grid table is refreshed (either via full page reload or AJAX table refresh).

### B. Test Database & Integration Test Setup
* Integration tests (PropertyManagerAccessTests, BogusSeeding) SHOULD use an in-memory SQLite database configured via \`DbContextOptionsBuilder\` in test setup.
* Ensure test database is re-seeded or cleared before each test to maintain isolation.
* Example setup pattern:
  \`\`\`csharp
  var options = new DbContextOptionsBuilder<ApplicationDbContext>()
      .UseSqlite("Data Source=:memory:")
      .Options;
  using var context = new ApplicationDbContext(options);
  context.Database.EnsureCreated();
  // Seed test data
  \`\`\`

### C. UnitType Dropdown Population Logic
When loading Create/Edit Unit forms:
1. **For Create**: Fetch all active UnitTypes (\`UnitType.ActiveBool == true\`).
2. **For Edit**: Fetch all active UnitTypes PLUS the current unit's assigned UnitType (even if inactive).
3. Sort dropdown options alphabetically by \`UnitTypeName\`.
4. Render using ASP.NET Core \`SelectListItem\` with proper \`selected\` attribute binding.

### D. Authorization on Modal Endpoints
* All \`*Modal\` endpoints (CreateModal, EditModal) MUST include \`[Authorize(Roles = "PropertyManager")]\` attribute.
* Applicant requests to these endpoints should receive HTTP 403 Forbidden.
* Direct access via URL bar (e.g., GET /Properties/CreateModal) should also be restricted.

### E. Database Migrations & EF Core
* After updating models, run: \`dotnet ef migrations add <MigrationName> --project RentalPropertyManager\`
* Apply migration before running application: \`dotnet ef database update --project RentalPropertyManager\`
* Ensure \`DbContext.OnModelCreating()\` includes \`builder.Entity<Unit>().Property(u => u.MonthlyRent).HasPrecision(18, 2);\`
